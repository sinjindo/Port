      1.1 핵심내용 요약 선박 ETA·하역계획이 바뀌면 냉동컨테이너의 전원 연결 시각을 다시 추정하고, 터미널 한 구역(주계량기 1개)의 24시간·15분 단위 전력수요를 재예측해, 예상 최대전력의 크기·발생시각과 '기존 대응계획이 놓치는 초과 구간'을 운영자에게 알리는 의사결정 지원 서비스. 설비 제어는 하지 않는다. 1.2 배경 및 필요성 - 냉동컨테이너는 육상 연결 시 터미널 에너지의 약 40%를 차지하고(van Duin et al. 2019, Wilmsmeier 2014 인용), 도착 냉동컨테이너 수가 일별 에너지 소비 분산의 76.6%를 설명한다(동 논문 결론, 일 단위 393개 관측, 2014–2015, 터미널 미공개). - 부산항만공사는 2022년 "입항 일정이 자주 바뀌어 AMP 자리에 접안하지 못하는" 문제로 60m 이동형 AMP 케이블을 도입했다. 일정 변동이 항만 전력 운영에 영향을 준다는 공식 사례다. - 부산항 냉동구역의 피크 문제·기존 EMS의 일정 반영 여부는 현장 확인 중이다(확인되지 않은 사실로 쓰지 않음). 1.3 활용 Scene 및 기술 10:00 예측 → 12:00 ETA 변경 통보 → 접안·하역·야드 이송·연결 시간차 모델로 연결 시각 재추정 → 15분 재예측 → 변경 전후 곡선·초과 구간·놓치는 구간 표시 → 운영자가 운영팀·전기팀과 협의. 기술: PORT-i/TOS 일정 입력(초기 CSV), 규칙 기반 시간차 모델, 릿지/XGBoost 예측(A/B/C 비교), 웹 대시보드(단일 HTML → FastAPI). 1.4 기대효과 - 피크 발생 전 사전 협의 시간 확보(시나리오에서 통보 후 첫 초과까지의 리드타임을 그대로 표시). - 기본요금은 월 최대수요가 해당 일에 결정될 때만 절감 가능(월 상한으로만 표기), 전력량요금 효과는 작음. - 정량 효과는 실데이터 검증 후 보고. 현재 수치는 모두 가상.
      2.4 AI·데이터 / 구현 구조
      입력 데이터(최소): 선박 ID·예정/변경 ETA·통보 시각(BPA PORT-i 또는 터미널, 협의 필요), 실제 접안·하역 시각(TOS), 냉동컨테이너 반입·반출·연결·해제 기록(TOS/냉동야드), 구역 15분 전력(kW, 기존 계량기 또는 한전 AMI), 기상예보(예측시점 기준), 요금 적용정보. 선박단위 ETA 공개 API는 2026-10-23 기준 확인되지 않아 초기에는 승인 CSV로 입력한다. 처리 구조: ① ETA 이력 저장(통보 시각 포함) → ② 시간차 모델(선석 대기, 하역 시작, 양하 속도, 야드 이송+연결 지연: 초기 가정값, 실측 기록으로 분포 보정) → ③ 15분 연결 수량·풀다운 지수·장비 작업 플래그 생성 → ④ 예측 모델 → ⑤ 사건 단위 초과 구간·놓치는 구간·경보 생성 → ⑥ 대시보드. 모델: A 전날 같은 시각(기준), B 시간대·외기·전날 값, C = B + 일정 변수. 릿지 회귀는 브라우저 내 가상데이터로 검증 완료, XGBoost는 동일 분할로 비교 예정. 검증 규칙: 시간순 분할, 예측시점 당시 정보만 사용(누출 방지), 입력 제거 실험, 반복 실험, 같은 시점에서 ETA 변경정보 유무 비교. v3 추가: 냉동컨테이너 열 모델(전원 차단 중 내부온도 상승 → 풀다운 전력), 긴급도 순 양하·소켓 배정, 통보 후 남은 크레인 슬롯만 재배치하는 15분 스케줄러, ESS는 남은 피크만 처리(종료 SOC 조건). 대안은 비용·탄소·피크·물동량·지연·온도·SOC 조건을 먼저 통과해야 후보가 된다. 구현 수준: 규칙 기반 시연 + 릿지 가상검증(완료), 실데이터 학습(미착수), FastAPI·권한·로그(계획).
      2.5 실행 계획
      1단계(공모전, 완료): 가상 구역 엔진·대시보드·사건 단위 검증·3D 상황도·부산항 터미널 대입. 2단계(현장 확인, 2–4주): 터미널 전기/운영 담당자 1명과 문제 확인, 냉동구역 계량 여부·연결 기록 유무 확인(질문 목록 준비됨). 3단계(데이터 협의, 2–4개월·개발과 별도): 계량 구역·읽기전용 데이터 제공 범위 합의. 1순위 후보 신항 7부두 DGT(완전자동화·전 장비 전기), 2순위 3·4부두(AMP 8기). 4단계(개발·검증, 3개월): 데이터 품질 점검 → 기준모델 → ETA·물류정보 추가 효과 검증 → 화면 → 과거 1개월 재현 시험. 5단계(관찰 운영, 2–3개월): 읽기전용 연계, 경보만 제공, 경보 1건 이상 업무 사용 여부 평가 후 확장 결정. 협약·데이터 제공은 미확정이며 기간은 추정이다. 2-6단계(2026 개장 예정) 설계에 계량·이벤트 로그 규격 제안을 병행한다.
      2.6 기대효과 / 성과 지표
      지표(모두 실데이터에서 산출 예정, 현재는 가상): - 예측: MAE·RMSE, 최대전력 크기 오차, 피크 시각 오차, ETA 변경 영향 구간 MAE(모델 B 대비 C 개선폭). - 경보: 사건 단위 재현율·정밀도(±60분 매칭), 통보→첫 초과 리드타임. - 운영: 경보가 업무에 사용된 건수, 전체 갱신시간(수신→화면, 목표 1분, 현재 모델 계산만 측정). - 경제: 기본요금 월 상한(최대수요 변화 × 기본요금 단가, 해당 월 피크일 때만), 전력량요금 차이(요금 인상 보정 반영). 기대효과는 '사전 협의 시간 확보'로 한정해 기술하고, 피크 감소율·비용 절감률은 실측 전 제시하지 않는다.
      2.7 리스크 / 대응
      - 데이터 미확보(최대 리스크): 냉동구역 단독 계량·연결 기록·ETA 이력이 없을 수 있음 → 범위 축소(반입량 기반 추정), 2-6단계 설계 제안, 신규 CT형 계량(견적 필요). - 현장 필요성 미확인: 담당자 확인 0건 → 2단계 인터뷰 결과에 따라 기능 재정의, 확인 전까지 '가설'로 기술. - 기존 EMS와 중복: BPA 에너지수요관리 플랫폼의 일정 반영 여부 미확인 → 입력(ETA 이력)·시점(통보 직후)·출력(놓치는 구간) 기준으로만 비교, '기존에 없음' 표현 사용 금지. - 예측 성능 미달: C가 B보다 낫지 않을 수 있음 → 경보·비교 화면 기능만 유지하고 결과 그대로 보고. - 경보 후 권한 없음: 연결 분산·작업 지연·ESS는 타 부서 권한 → 가치는 협의 시간 확보로 한정, 자동 제어 제외. - 3D·화면 과장 오해: 개념 배치 명시, 모든 수치에 데이터 수준 표시. - 요금·규정 변동: 요금표 최신판 확인 전 보정값 사용, 계약 조건은 터미널 확인.

      1. 하역→이송→연결을 열 모델로, 긴급 컨테이너 우선 배정내부온도 상태 변수(냉동 τ 100h는 CSIRO 2007 실측 환산, 허용 편차·오프라인 4h는 van Duin 2019 Table 1), 3종 화물, 한도 도달 시간 순 양하 + 소켓 수 제약·대기 (과정 탭)냉장·바나나 τ, k, 유닛 상한, 화물 비율은 가정. 순서 배정은 온도 위반을 줄이지만 총 비전원 시간은 못 줄인다 — 이송 지연 단축이 더 크다

      3D의 역할과 한계

      역할은 "언제, 무엇 때문에 전력이 겹치는가"를 한 장면에서 보이게 하는 것이다. 전력 벽의 막대 색이 원인(크레인·냉동·기본)을, 높이가 크기를, 빨간 부분이 초과를, 뒷줄이 변경 전을 보여준다. 한계: 배치는 개념이며 실제 부산항이 아니고, 설비 위치와 전기 계통 연결은 다르다. 심사에서는 3D가 아니라 "입력을 바꾸면 결과가 바뀌는가"가 평가되므로, 발표에서는 3D를 30초 이내로 쓰고 답 카드와 그래프에 시간을 쓰는 편이 낫다.
